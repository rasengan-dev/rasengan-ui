# Button

Triggers an action. Seven variants, six tones and six sizes; the shape, type, depth and press come from the village.

<ComponentPreview name="button" />

## Installation

```bash title="Terminal"
npx rasengan-ui add button
```

Or with the shadcn CLI, from the registry:

```bash title="Terminal"
npx shadcn@latest add https://ui.rasengan.dev/r/base/button.json
```

## Usage

```tsx title="app/save.tsx"
import { Button } from "@/components/ui/button";

export function Save() {
  return <Button onClick={save}>Save changes</Button>;
}
```

### Variants

`default` for the main action of a view, `secondary` and `outline` for the others, `soft` for a quieter one in colour,
`ghost` inside toolbars and lists, `destructive` for an action that deletes, and `link` for an action that reads as
text. In Onmyōton, where the primary colour is the foreground, `link` is underlined: it cannot rely on colour alone.

```tsx
<Button variant="outline">Preview</Button>
<Button variant="destructive">Delete project</Button>
```

### Tones

`tone` is the colour, apart from the style: `primary` by default, `neutral` for the village's ink, and `success`,
`warning`, `info` or `destructive` for an action that carries that meaning. It colours `default`, `soft` and `link`.
`outline` and `ghost` keep their neutral look in `primary`, as in shadcn, and take the tone's colour in the others;
`secondary` stays grey. `variant="destructive"` is shorthand for `variant="default" tone="destructive"`.

<ComponentPreview name="button" demo="button-tones" />

```tsx
<Button variant="soft" tone="success">Approve</Button>
<Button variant="outline" tone="destructive">Leave team</Button>
```

### Sizes

`sm`, `default` and `lg` follow the village's control heights (`--control-sm`, `--control-md`, `--control-lg`): Iwa is
denser than Kiri. `icon-sm`, `icon` and `icon-lg` are squares of those heights and need an `aria-label`.

<ComponentPreview name="button" demo="button-sizes" />

```tsx
<Button size="icon" aria-label="Add a teammate">
  <PlusIcon />
</Button>
```

### As a link or another element

The button renders a `<button>`. To render another element with the button's look, pass it to `render`, or put
`buttonVariants()` on it.

```tsx
<Button render={<a href="/pricing" />} nativeButton={false}>See pricing</Button>

<Link to="/docs" className={buttonVariants({ variant: "outline" })}>Read the docs</Link>
```

## Accessibility

- A `<button type="button">`: it is focusable and fires on <kbd>Enter</kbd> and <kbd>Space</kbd>.
- The focus ring is the village's (a halo in Konoha and Kiri, a ring with a gap in Iwa) and only shows for the keyboard.
- `disabled` keeps the button out of the tab order. To keep it focusable while it can't be pressed (a loading state,
  for example), pass `focusableWhenDisabled`.
- An icon-only button needs an `aria-label`.

## API reference

The props of Base UI's [Button](https://base-ui.com/react/components/button), plus:

| Prop | Type | Default |
| --- | --- | --- |
| `variant` | `"default" \| "secondary" \| "outline" \| "ghost" \| "soft" \| "destructive" \| "link"` | `"default"` |
| `tone` | `"neutral" \| "primary" \| "success" \| "warning" \| "info" \| "destructive"` | `"primary"` |
| `size` | `"sm" \| "default" \| "lg" \| "icon-sm" \| "icon" \| "icon-lg"` | `"default"` |
| `className` | `string` | |

`buttonVariants({ variant, tone, size })` returns the same classes, for elements that should look like a button.
